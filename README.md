# domain-expiry

Prometheus exporter for domain registration expiry. It looks domains up over WHOIS
(via [python-whois](https://github.com/richardpenman/whois)) and works like
blackbox_exporter: Prometheus asks `/probe?target=<domain>` for each domain.

`.com`, `.ee` and `.eu` are tested and guaranteed. Other TLDs work if python-whois can parse
their registry's WHOIS output. See [docs/adr](docs/adr) for why it's WHOIS and not RDAP, and
[GLOSSARY.md](GLOSSARY.md) for the terms used here.

_AI disclosure: most of this project was generated by Claude Code._

## Metrics

`/probe?target=example.com` returns:

| Metric | Meaning |
|---|---|
| `probe_success{domain}` | 1 if the lookup succeeded. A domain that is not registered still counts as success. |
| `probe_duration_seconds{domain}` | Time taken by the probe (cache hits are fast). |
| `domain_registered{domain}` | 1 if the registry has a record for the domain, 0 if not. Absent when the lookup failed. |
| `domain_expiry_timestamp_seconds{domain}` | When the registration expires (Unix time). **Never present for `.eu`**: EURid's WHOIS doesn't publish it. |
| `domain_status{domain,status}` | 1 for each registry status currently on the domain, as snake_case EPP codes (`client_hold`, `redemption_period`, `ok`, …). Not available for `.eu`. |

Only registrable domains are accepted. `www.example.com` or `com` get HTTP 400.

`/metrics` has the exporter's own metrics: `domain_expiry_exporter_lookups_total{outcome}`,
`domain_expiry_exporter_cache_requests_total{result}`, `domain_expiry_exporter_cache_entries`,
plus the standard process metrics.

### Caching

Results are kept in memory: successes for 12h and failures for 15m, up to 10,000 domains
(least recently probed dropped first). A probe is usually served from cache, so registries
aren't hammered whatever your scrape interval. When a cached result expires and the refresh
fails, the probe reports the failure. It never serves a stale expiry.

Lookups that miss the cache run one at a time in the background, each with an overall 20s
deadline. A probe waits for its lookup only up to its scrape timeout. If the lookup takes
longer, the probe reports failure, but the lookup carries on and its result is cached for the
next scrape. So right after a restart with many domains, some scrapes fail until the cache
fills. Health checks and `/metrics` answer even while lookups are slow.

## Running

```bash
docker run -p 9019:9019 ghcr.io/anroots/domain-expiry
curl 'localhost:9019/probe?target=example.com'
```

| Environment variable | Default |
|---|---|
| `DOMAIN_EXPIRY_LISTEN_ADDRESS` | `0.0.0.0` |
| `DOMAIN_EXPIRY_PORT` | `9019` |
| `DOMAIN_EXPIRY_CACHE_TTL_SECONDS` | `43200` |
| `DOMAIN_EXPIRY_FAILURE_TTL_SECONDS` | `900` |
| `DOMAIN_EXPIRY_CACHE_MAX_ENTRIES` | `10000` |
| `DOMAIN_EXPIRY_LOOKUP_TIMEOUT_SECONDS` | `20` (deadline for one WHOIS lookup; a probe waits at most this, or the scrape timeout minus 0.5s if lower) |
| `DOMAIN_EXPIRY_TIMEOUT_OFFSET_SECONDS` | `0.5` |
| `DOMAIN_EXPIRY_LOG_LEVEL` | `INFO` |

### Kubernetes

```bash
helm install domain-expiry oci://ghcr.io/anroots/charts/domain-expiry \
  --set probe.enabled=true --set 'probe.domains={example.com,internet.ee,eurid.eu}'
```

`probe.enabled` creates a Prometheus Operator `Probe` resource (needs the operator's CRDs).

### Plain Prometheus

```yaml
scrape_configs:
  - job_name: domain-expiry
    metrics_path: /probe
    scrape_interval: 1h
    scrape_timeout: 15s
    static_configs:
      - targets: [example.com, internet.ee, eurid.eu]
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - source_labels: [__param_target]
        target_label: instance
      - target_label: __address__
        replacement: domain-expiry:9019
```

## Example alerts

```yaml
- alert: DomainExpiringSoon
  expr: domain_expiry_timestamp_seconds - time() < 30 * 86400
  for: 1h
- alert: DomainNotRegistered
  expr: domain_registered == 0
- alert: DomainOnHold
  expr: domain_status{status=~"client_hold|server_hold|redemption_period|pending_delete"} == 1
- alert: DomainExpiryProbeFailing
  expr: probe_success{job="domain-expiry"} == 0
  for: 1d
```

## Development

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/pytest          # unit tests against recorded WHOIS replies
.venv/bin/pytest -m live  # real WHOIS lookups (also run weekly in CI)
```

## Alternatives

- [caarlos0/domain_exporter](https://github.com/caarlos0/domain_exporter): Go WHOIS exporter with a blackbox-style `/probe` endpoint and per-domain WHOIS server overrides.
- [shift/domain_exporter](https://github.com/shift/domain_exporter): Go WHOIS exporter that reads domains from a config file and exposes `domain_expiration_seconds`.
- [numero33/domain_exporter](https://github.com/numero33/domain_exporter): Go WHOIS exporter for domains listed in a config file, served on `/metrics`.
- [adamdecaf/rdap_exporter](https://github.com/adamdecaf/rdap_exporter): Go exporter based on shift/domain_exporter that uses RDAP instead of WHOIS and reports days until expiry.
